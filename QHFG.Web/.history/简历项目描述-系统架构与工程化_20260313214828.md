# 简历项目描述 - 系统架构与工程化

## 项目系统架构设计

### 1. 前端项目框架搭建

**技术选型与架构设计**
- 采用 **Vue 3.4.21** + **Vite 5.4.10** 构建现代化前端应用，使用 Composition API 提升代码可维护性
- 基于 **模块化架构** 设计，采用组件化开发模式，实现高内聚低耦合的代码结构
- 使用 **Vue Router 4.4.5** 实现单页应用路由管理，配置 Hash 路由模式适配部署环境
- 集成 **Vue I18n 11.0** 实现国际化多语言支持（中英文），支持语言切换和本地存储持久化

**核心依赖管理**
- 地图引擎：集成 **OpenLayers 10.3.1**（2D地图）和 **Cesium 1.99**（3D地球），实现双引擎地图可视化
- UI组件库：同时集成 **Element Plus 2.8.8** 和 **Ant Design Vue 4.x**，满足不同业务场景需求
- 数据可视化：使用 **ECharts 5.5.1** + **vue-echarts 7.0.3** 实现图表展示
- 地理空间计算：集成 **@turf/turf 6.5.0** 处理地理空间数据计算

### 2. Pinia 状态管理

**状态管理架构设计**
- 采用 **Pinia 2.3.1** 作为全局状态管理方案，替代传统 Vuex，提供更简洁的 API 和更好的 TypeScript 支持
- 使用 **Composition API 风格**（Setup Store）定义 Store，充分利用 Vue 3 的响应式系统
- 配置 **pinia-plugin-persistedstate 4.1.3** 实现状态持久化（支持 localStorage 存储）

**Store 设计模式**
```javascript
// 使用 Setup Store 模式，利用 Composition API
export const useLayerStore = defineStore("layer", () => {
  // 使用 shallowRef 优化大对象性能
  const layerList = shallowRef([]);
  const selectedLayerList = shallowRef([]);
  const regionList = shallowRef([]);
  
  // 提供响应式的 getter 和 action
  const setLayerList = (val) => { layerList.value = val; };
  
  return { layerList, setLayerList, ... };
});
```

**状态管理实践**
- 实现图层数据、选中状态、行政区划等全局状态的统一管理
- 通过 Store 实现组件间数据共享，减少 props 传递层级
- 使用 `shallowRef` 优化大数组/对象性能，避免深度响应式带来的性能损耗

### 3. 工程化配置

**构建工具配置（Vite）**
- 使用 **Vite 5.4.10** 作为构建工具，实现快速开发热更新和高效生产构建
- 配置 **路径别名**（`@` → `./src`），简化模块导入路径
- 集成 **vite-plugin-cesium** 处理 Cesium 库的特殊构建需求
- 配置 **开发服务器代理**，解决跨域问题，代理 `/map/get` 和 `/statistical` 接口

**代码质量与开发体验**
- 使用 **unplugin-auto-import** 实现 Vue API 自动导入，减少重复代码
- 配置 **unplugin-vue-components** + **ElementPlusResolver** 实现组件自动按需导入
- 集成 **vite-plugin-vue-devtools** 提供 Vue 开发调试工具
- 配置 **TypeScript 5.7.3** 支持（项目逐步迁移中）

**样式工程化**
- 支持 **Less 4.2.1** 和 **SCSS** 预处理器，使用现代编译器 API
- 配置全局样式文件（`base.scss`），统一管理项目样式变量和基础样式
- 使用 **CSS Modules** 和 **Scoped CSS** 实现样式隔离

**构建优化**
- 配置 **代码分割**（Code Splitting），按 node_modules 自动分包，优化首屏加载
- 设置 **chunkSizeWarningLimit: 1500KB**，控制单个 chunk 大小
- 使用 **Rollup** 进行生产构建，配置 `manualChunks` 实现精细化分包策略
- 优化 Cesium 等大型库的加载，避免阻塞主应用

**项目结构设计**
```
src/
├── components/          # 组件目录
│   ├── dataService/    # 数据服务模块（2D/3D地图）
│   └── home/           # 首页模块
├── stores/             # Pinia Store
├── router/             # 路由配置
├── request/            # HTTP 请求封装（Axios）
├── utils/              # 工具函数
├── assets/             # 静态资源
└── views/              # 页面组件
```

**开发规范**
- 采用 **ES Module**（`type: "module"`）作为模块系统
- 使用 **路径别名** `@/` 统一引用规范
- 配置 **JSConfig** 提供 IDE 智能提示支持
- 实现组件按功能模块划分，提高代码可维护性
