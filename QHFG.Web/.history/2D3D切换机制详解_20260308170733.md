# 2D/3D地图切换机制详解

## 📋 问题1：changeMap 是怎么切换 2D/3D的？

---

## 🎯 一、切换机制（3个关键点）

### 1. **状态控制** - `dimensionFlag`

```javascript
// DataService.vue
const dimensionFlag = ref(2);  // 2 = 2D, 3 = 3D

const changeMap = () => {
  if (dimensionFlag.value == 2) {
    dimensionFlag.value = 3;  // 切换到3D
  } else if (dimensionFlag.value == 3) {
    dimensionFlag.value = 2;  // 切换到2D
  }
};
```

**作用：** 用一个状态变量控制当前显示的是2D还是3D

---

### 2. **显示控制** - `v-show`

```vue
<!-- DataService.vue 模板 -->
<Map2D
  v-show="dimensionFlag == 2"  <!-- 当 dimensionFlag == 2 时显示 -->
  :qgsMapPath="qgsMapPath"
  :tifMapPath="tifMapPath"
/>

<Map3D
  v-show="dimensionFlag == 3"  <!-- 当 dimensionFlag == 3 时显示 -->
  :qgsMapPath="qgsMapPath"
  :tifMapPath="tifMapPath"
/>
```

**工作原理：**
- `v-show="dimensionFlag == 2"`：当条件为 `true` 时，元素显示（`display: block`）
- `v-show="dimensionFlag == 3"`：当条件为 `true` 时，元素显示
- **两个组件同时存在于DOM中**，只是通过CSS控制显示/隐藏

**为什么用 `v-show` 而不是 `v-if`？**
- ✅ `v-show`：元素始终在DOM中，切换时只是改变CSS的`display`属性，**性能更好**
- ❌ `v-if`：切换时会销毁/重建组件，**性能较差**，但会释放内存

---

### 3. **完整切换流程**

```
用户点击切换按钮
    ↓
changeMap() 函数执行
    ↓
dimensionFlag.value = 3  (从2改为3)
    ↓
Vue响应式系统检测到变化
    ↓
重新计算 v-show 条件
    ↓
Map2D: v-show="2 == 2" → false → 隐藏 (display: none)
Map3D: v-show="3 == 3" → true  → 显示 (display: block)
    ↓
视觉上完成切换
```

---

## 🔍 二、为什么切换时不需要重新生成数据？

**关键点：** 两个地图组件**同时存在**，都接收相同的props

```javascript
// DataService.vue
const qgsMapPath = ref("");
const tifMapPath = ref("");

// 当用户选择结果项时，生成地图路径
const handleResultSelect = (checked, index) => {
  qgsMapPath.value = `/io/data/${mapPathUrlList.value[index]}/${layerUrl.value}.qgs`;
  tifMapPath.value = `${layerUrl.value}.tif`;
  // 两个组件都能接收到这个变化
};

// 模板中：两个组件都绑定相同的props
<Map2D :qgsMapPath="qgsMapPath" :tifMapPath="tifMapPath" />
<Map3D :qgsMapPath="qgsMapPath" :tifMapPath="tifMapPath" />
```

**好处：**
- ✅ 切换时**不需要重新生成数据**
- ✅ 切换**瞬间完成**，用户体验好
- ✅ 两个地图**数据完全同步**

## 📋 问题2：bus.emit("map3DVisible") 是干什么的？

---

## 🎯 一、作用：通知3D地图开始自动旋转

### 完整代码流程

```javascript
// DataService.vue - 父组件
const changeMap = () => {
  if (dimensionFlag.value == 2) {
    dimensionFlag.value = 3;
    // 切换到3D地图时，延迟通知Map3D组件开始旋转
    setTimeout(() => {
      bus.emit("map3DVisible");  // ⭐ 发送事件
    }, 100);
  }
};
```

```javascript
// Map3D.vue - 子组件
// 监听父组件的切换事件
bus.on("map3DVisible", () => {
  setTimeout(() => {
    // 清除之前的点位和弹窗，恢复初始状态
    closePopover();

    if (viewer && !autoRotateInterval) {
      startAutoRotate();  // ⭐ 开始自动旋转
    }
  }, 500);
});

// 自动旋转函数
function startAutoRotate() {
  if (!viewer || autoRotateInterval || !allowAutoRotate) return;
  const rotationSpeed = 0.002;
  autoRotateInterval = setInterval(() => {
    if (viewer && viewer.scene && viewer.scene.camera) {
      viewer.scene.camera.rotateRight(rotationSpeed);  // 每帧旋转0.002弧度
    }
  }, 16);  // 约60fps
}
```

---

## 🔍 二、为什么需要这个事件？

### 问题场景

**场景1：组件已经挂载，但被隐藏**
- Map3D组件在页面加载时就已经创建（因为使用`v-show`）
- 但初始状态是隐藏的（`dimensionFlag = 2`）
- 当切换到3D时，需要**主动触发**自动旋转

**场景2：切换时机问题**
- 如果在地图加载完成时就开始旋转，但用户还在看2D地图
- 切换到3D时，旋转可能已经停止了
- 需要**在切换时重新启动**旋转

---

## 🎯 三、为什么使用 setTimeout 延迟？

### 代码分析

```javascript
// DataService.vue
setTimeout(() => {
  bus.emit("map3DVisible");
}, 100);  // 延迟100ms
```

**原因：**
1. **等待DOM更新**：`v-show` 改变后，需要等待Vue完成DOM更新
2. **确保组件可见**：确保Map3D组件已经显示在页面上
3. **避免时序问题**：如果立即发送事件，Map3D可能还没准备好

```javascript
// Map3D.vue
bus.on("map3DVisible", () => {
  setTimeout(() => {
    startAutoRotate();
  }, 500);  // 再延迟500ms
});
```

**原因：**
1. **等待地图渲染**：确保Cesium地图已经完全渲染
2. **确保viewer可用**：确保viewer对象已经初始化完成
3. **避免冲突**：如果之前有旋转，先停止再启动

## 🔍 五、自动旋转的实现细节

### startAutoRotate() 函数详解

```javascript
function startAutoRotate() {
  // 1. 检查前置条件
  if (!viewer || autoRotateInterval || !allowAutoRotate) return;
  
  // 2. 设置旋转速度
  const rotationSpeed = 0.002;  // 每次旋转0.002弧度（约0.11度）
  
  // 3. 创建定时器，每16ms执行一次（约60fps）
  autoRotateInterval = setInterval(() => {
    if (viewer && viewer.scene && viewer.scene.camera) {
      viewer.scene.camera.rotateRight(rotationSpeed);
      // rotateRight: 相机向右旋转（地球向左转）
    }
  }, 16);
  
  // 4. 添加点击事件，点击后停止旋转
  viewer.scene.canvas.addEventListener("click", handleMapClickToStopRotate, {
    once: true,  // 只触发一次
  });
}
```

**关键点：**
- **旋转速度**：`0.002` 弧度/帧 ≈ `0.11` 度/帧
- **帧率**：`16ms` 间隔 ≈ `60fps`
- **总速度**：`0.11度/帧 × 60帧/秒 = 6.6度/秒`
- **一圈时间**：`360度 ÷ 6.6度/秒 ≈ 54秒`（约1分钟转一圈）

## 🎯 六、为什么需要多个启动旋转的机制？

### Map3D中有3种启动旋转的方式

#### 1. **地图加载完成后自动启动**
```javascript
// onMounted 中
viewer.scene.globe.tileLoadProgressEvent.addEventListener(() => {
  if (viewer.scene.globe.tilesLoaded) {
    startAutoRotate();  // 地图加载完成后启动
  }
});
```

#### 2. **延迟2秒后启动（备用方案）**
```javascript
setTimeout(() => {
  if (!autoRotateInterval) {
    startAutoRotate();  // 备用方案，确保能启动
  }
}, 2000);
```

#### 3. **接收到map3DVisible事件后启动** ⭐
```javascript
bus.on("map3DVisible", () => {
  setTimeout(() => {
    if (viewer && !autoRotateInterval) {
      startAutoRotate();  // 切换时启动
    }
  }, 500);
});
```

**为什么需要3种方式？**
- ✅ **方式1**：正常情况，地图加载完成后自动启动
- ✅ **方式2**：备用方案，防止方式1失败
- ✅ **方式3**：**关键**，处理从2D切换到3D的情况

## 💡 七、设计亮点

### 1. **解耦设计**
- 父组件（DataService）不需要知道Map3D的内部实现
- 通过事件总线通信，实现解耦

### 2. **用户体验优化**
- 切换到3D时自动开始旋转，增强视觉效果
- 点击地图后停止旋转，用户可以交互

### 3. **容错机制**
- 多个启动旋转的机制，确保在各种情况下都能启动
- 延迟执行，避免时序问题

## 📝 八、面试重点问题

### Q1: 如何实现2D/3D地图切换？

**答案：**
1. **状态控制**：使用 `dimensionFlag` 变量（2=2D, 3=3D）
2. **显示控制**：使用 `v-show` 根据状态显示/隐藏组件
3. **数据统一**：两个组件接收相同的props，保证数据一致
4. **事件通知**：切换到3D时，通过事件总线通知开始旋转

**关键代码：**
```javascript
const dimensionFlag = ref(2);
const changeMap = () => {
  dimensionFlag.value = dimensionFlag.value === 2 ? 3 : 2;
  if (dimensionFlag.value === 3) {
    setTimeout(() => {
      bus.emit("map3DVisible");
    }, 100);
  }
};
```

### Q2: 为什么使用 v-show 而不是 v-if？

**答案：**
- **v-show**：元素始终在DOM中，切换时只改变CSS的`display`属性
  - ✅ 切换速度快，性能好
  - ✅ 适合频繁切换的场景
  - ❌ 初始渲染时两个组件都会创建（内存占用）

- **v-if**：切换时会销毁/重建组件
  - ✅ 初始渲染时只创建显示的组件（节省内存）
  - ❌ 切换时需要重新创建组件（性能较差）

**选择v-show的原因：**
- 2D/3D切换是**频繁操作**，需要快速响应
- 两个地图组件都需要**保持状态**（如地图缩放级别）
- 使用v-show可以**保持组件状态**，切换时不需要重新初始化

### Q3: bus.emit("map3DVisible") 的作用是什么？

**答案：**
1. **通知3D地图开始自动旋转**：切换到3D时，触发地球自动旋转动画
2. **解耦设计**：父组件不需要知道Map3D的内部实现，通过事件通信
3. **时序控制**：延迟执行，确保DOM更新和地图渲染完成后再启动旋转

**为什么需要延迟？**
- 等待Vue完成DOM更新（v-show生效）
- 等待Cesium地图完全渲染
- 避免时序问题导致旋转启动失败
