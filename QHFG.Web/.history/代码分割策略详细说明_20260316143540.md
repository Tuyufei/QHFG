## ⚙️ 配置代码解析

### 1. **完整配置**

```javascript
// vite.config.js
build: {
  chunkSizeWarningLimit: 1500,  // 允许单个chunk最大1500KB
  rollupOptions: {
    output: {
      manualChunks(id) {
        // id: 文件的完整路径
        // 例如: "node_modules/vue/dist/vue.runtime.esm-bundler.js"
        
        if (id.includes('node_modules')) {
          // 提取包名，按包名分割
          return id.toString().split('node_modules/')[1].split('/')[0].toString();
        }
      }
    }
  }
}
```

### 2. **配置说明**

- **chunkSizeWarningLimit: 1500**：允许单个chunk最大1500KB，超过会警告但不报错
- **manualChunks(id)**：自定义代码分割函数，接收文件路径id，返回chunk名称
- **id.includes('node_modules')**：判断是否是npm包
- **split('node_modules/')[1]**：提取node_modules后面的路径
- **split('/')[0]**：提取包名（第一个斜杠前的部分）

## 🔍 工作原理详解

### 1. **文件路径解析过程**

#### 示例1：Vue框架

```javascript
// 输入：文件路径

// 步骤1：检查是否包含 node_modules
id.includes('node_modules')  // true ✅

// 步骤2：提取 node_modules 后面的路径
id.split('node_modules/')  
// 结果: ["", "vue/dist/vue.runtime.esm-bundler.js"]
// 取索引1: "vue/dist/vue.runtime.esm-bundler.js"

// 步骤3：提取包名（第一个斜杠前的部分）
"vue/dist/vue.runtime.esm-bundler.js".split('/')
// 结果: ["vue", "dist", "vue.runtime.esm-bundler.js"]
// 取索引0: "vue"

// 步骤4：返回chunk名称
return "vue"
// 结果：所有vue相关文件打包到 vue.js

## 📊 打包结果对比

### 1. **不使用代码分割（默认情况）**

```
dist/
├── index.html
└── assets/
    └── index-abc123.js  (5.2MB)  ← 所有代码打包在一起
```

**问题分析**：
- ❌ **首屏加载慢**：用户需要下载5.2MB才能看到页面
- ❌ **缓存效率低**：修改一行业务代码，整个文件hash变化，用户需要重新下载5.2MB
- ❌ **并行加载差**：只能单线程下载一个大文件
- ❌ **按需加载难**：即使用户不访问地图页面，也要加载Cesium和OpenLayers

### 2. **使用代码分割后**

```
dist/
├── index.html
└── assets/
    ├── index-abc123.js           (200KB)  ← 业务代码
    ├── vue-def456.js             (150KB)  ← Vue框架
    ├── element-plus-ghi789.js    (800KB)  ← Element Plus UI组件库
    ├── cesium-jkl012.js          (2MB)    ← Cesium 3D地图引擎
    ├── ol-mno345.js              (500KB)  ← OpenLayers 2D地图引擎
    ├── echarts-pqr678.js         (600KB)  ← ECharts图表库
    ├── vue-router-stu901.js      (30KB)   ← Vue Router
    ├── pinia-vwx234.js           (10KB)   ← Pinia状态管理
    ├── vue-i18n-yza567.js        (20KB)   ← Vue I18n国际化
    ├── axios-bcd890.js           (20KB)   ← Axios请求库
    ├── lodash-efg123.js           (70KB)   ← Lodash工具库
    ├── ant-design-vue-hij456.js  (400KB)  ← Ant Design Vue
    └── vendor-klm789.js          (100KB)  ← 其他小库
```

**优势分析**：
- ✅ **首屏加载快**：只需要下载200KB业务代码 + 150KB Vue = 350KB
- ✅ **缓存效率高**：修改业务代码，只有index.js的hash变化，其他库文件不变
- ✅ **并行加载**：浏览器可以同时下载多个文件（HTTP/2多路复用）
- ✅ **按需加载**：用户访问地图页面时才加载cesium.js和ol.js

## 🚀 性能提升效果

### 1. **首屏加载时间对比**

#### 场景1：用户首次访问首页

**不使用代码分割**：
```
需要下载：index.js (5.2MB)
下载时间（4G网络）：5.2MB / 1MB/s ≈ 5.2秒
首屏显示时间：5.2秒 + 解析时间 ≈ 6秒
```

**使用代码分割**：
```
需要下载：
- index.js (200KB)      → 0.2秒
- vue.js (150KB)        → 0.15秒
- element-plus.js (800KB) → 0.8秒（并行下载）
- vendor.js (100KB)     → 0.1秒（并行下载）

并行下载总时间：max(0.2, 0.15, 0.8, 0.1) ≈ 0.8秒
首屏显示时间：0.8秒 + 解析时间 ≈ 1.2秒
```

**提升**：从6秒降到1.2秒，**提升80%** 🎉

#### 场景2：用户访问地图页面（需要加载Cesium）

**不使用代码分割**：
```
需要下载：index.js (5.2MB)  ← 包含所有代码
下载时间：5.2秒
```

**使用代码分割**：
```
需要下载：
- index.js (200KB)      → 0.2秒
- vue.js (150KB)        → 0.15秒
- cesium.js (2MB)       → 2秒（按需加载）
- ol.js (500KB)         → 0.5秒（按需加载）

并行下载总时间：max(0.2, 0.15, 2, 0.5, 0.8) ≈ 2秒
```

**提升**：虽然总时间差不多，但**首屏更快**（0.35秒 vs 5.2秒），地图功能按需加载

### 2. **缓存命中率对比**

#### 场景：修改业务代码后重新部署

**不使用代码分割**：
```
修改前：index-abc123.js (5.2MB)
修改后：index-xyz789.js (5.2MB)  ← hash完全变化
用户需要重新下载：5.2MB ❌

**使用代码分割**：
```

修改后：
- index-xyz789.js (200KB)      ← hash变化，需要重新下载

用户需要重新下载：200KB ✅
缓存命中率：(150KB + 2MB) / (200KB + 150KB + 2MB) ≈ 91%
```

**提升**：缓存命中率从0%提升到91%，**用户只需下载200KB而不是5.2MB** 🎉

## 🎯 总结

### ✅ 代码分割策略的优势

1. **首屏加载快**：只加载必要代码，首屏时间从6秒降到1.2秒
2. **缓存效率高**：修改代码不影响库文件，缓存命中率91%
3. **按需加载**：用户访问特定功能时才加载对应库
4. **并行下载**：浏览器可以同时下载多个文件，提升速度

### ✅ 实现原理

1. **按包名分割**：每个npm包单独打包成一个chunk
2. **自动识别**：通过文件路径自动识别包名
3. **零配置**：只需配置manualChunks函数，自动处理所有依赖

### ✅ 实际效果

- **首屏加载**：从5.2MB降到350KB（93%↓）
- **缓存命中**：从0%提升到91%
- **用户体验**：首屏时间从6秒降到1.2秒（80%↓）

   - Vue框架 → vue.js (150KB)
