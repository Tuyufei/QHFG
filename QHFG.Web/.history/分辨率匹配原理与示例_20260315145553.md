## 什么是分辨率（Resolution）

### 定义

**分辨率（Resolution）**：表示地图上**每个像素代表的地理距离**。

- **单位**：度/像素（对于 EPSG:4326 地理坐标系）
- **含义**：数值越小，地图越详细（放大）；数值越大，地图越粗略（缩小）

### 公式

```
分辨率 = 地理范围 / 像素数量
```

对于 EPSG:4326（地理坐标系）：
```
分辨率 = 地理范围（度）/ 瓦片像素数
```

## 为什么需要匹配分辨率

### 核心问题

**OpenLayers 需要知道每个缩放级别对应的分辨率，才能正确计算需要请求哪些瓦片。**

### 工作流程

```
用户缩放地图
    ↓
OpenLayers 计算当前分辨率
    ↓
根据分辨率确定缩放级别（zoom level）
    ↓
根据缩放级别和分辨率计算瓦片坐标
    ↓
生成 WMS 请求 URL（包含 BBOX、WIDTH、HEIGHT）
    ↓
服务端根据请求参数生成瓦片
```

### 如果不匹配会发生什么？

#### 场景1：客户端分辨率 > 服务端分辨率

```javascript
// 客户端配置
resolutions: [0.703125, 0.3515625, 0.17578125]

// 服务端实际支持
// 假设服务端只支持：0.5, 0.25, 0.125

// 问题：
// 客户端请求分辨率 0.3515625 的瓦片
// 服务端没有这个分辨率，返回错误或使用最接近的分辨率
// 结果：瓦片错位、显示不清晰、拼接错误
```

#### 场景2：客户端分辨率 < 服务端分辨率

```javascript
// 客户端配置
resolutions: [0.5, 0.25, 0.125]

// 服务端实际支持
// 假设服务端支持：0.703125, 0.3515625, 0.17578125

// 问题：
// 客户端请求分辨率 0.5 的瓦片
// 服务端返回分辨率 0.3515625 的瓦片（更详细）
// 结果：瓦片大小不匹配、显示错位、性能浪费
```

## 分辨率如何计算

### 标准计算公式（EPSG:4326）

对于 EPSG:4326 地理坐标系，全球范围是：
- **经度范围**：360 度（-180 到 180）
- **纬度范围**：180 度（-90 到 90）

#### 缩放级别 0（最粗略）

```
分辨率 = 360度 / (瓦片数量 × 瓦片宽度)

假设：2个瓦片 × 1024像素 = 2048像素
分辨率 = 360 / 2048 = 0.17578125 度/像素
```

#### 缩放级别 1

```
分辨率 = 0.17578125 / 2 = 0.087890625 度/像素
```

#### 缩放级别 2

```
分辨率 = 0.087890625 / 2 = 0.0439453125 度/像素
```

### 项目中的配置

```javascript
// Map2D.vue 第77-82行
resolutions: [
  0.703125,      // 缩放级别 0：每像素 = 0.703125 度
  0.3515625,     // 缩放级别 1：每像素 = 0.3515625 度
  0.17578125,    // 缩放级别 2：每像素 = 0.17578125 度
]
```

**计算过程**：
- 缩放级别 0：`360度 / (2瓦片 × 256像素) = 0.703125`
- 缩放级别 1：`0.703125 / 2 = 0.3515625`
- 缩放级别 2：`0.3515625 / 2 = 0.17578125`

## 不匹配会导致什么问题

### 问题1：瓦片错位

#### 场景描述
```javascript
// 客户端配置
resolutions: [0.703125, 0.3515625, 0.17578125]

// 服务端实际支持
resolutions: [0.5, 0.25, 0.125]

// 用户缩放到级别 1
// 客户端计算：需要分辨率 0.3515625 的瓦片
// 服务端返回：分辨率 0.25 的瓦片（更详细）
// 结果：瓦片大小不匹配，导致错位
```

#### 视觉效果
```
正确情况：
┌─────┬─────┐
│瓦片1│瓦片2│
├─────┼─────┤
│瓦片3│瓦片4│
└─────┴─────┘

错误情况（分辨率不匹配）：
┌──────┬──────┐
│瓦片1 │瓦片2 │
│      │      │
├──────┼──────┤
│瓦片3 │瓦片4 │
│      │      │
└──────┴──────┘
  ↑ 瓦片重叠或间隙
```

### 问题2：瓦片请求失败

```javascript
// 客户端请求
GET /map/getmap?BBOX=-180,90,0,0&WIDTH=1024&HEIGHT=1024&RESOLUTION=0.3515625

// 服务端不支持分辨率 0.3515625
// 返回：400 Bad Request 或 使用默认分辨率
// 结果：瓦片加载失败或显示错误
```

### 问题3：性能浪费

```javascript
// 客户端需要分辨率 0.5 的瓦片
// 服务端返回分辨率 0.25 的瓦片（更详细，文件更大）
// 结果：
// - 下载时间增加
// - 内存占用增加
// - 渲染性能下降
```

### 例子3：完整的请求过程

#### 场景：用户缩放到级别 1，查看北京地区

**步骤1：OpenLayers 计算当前分辨率**
```javascript
// 用户缩放级别：zoom = 1
// 查找 resolutions 数组索引 1
const currentResolution = resolutions[1];  // 0.3515625 度/像素
```

**步骤2：计算瓦片坐标**
```javascript
// 当前视图范围：北京地区
// BBOX: [116.0, 39.5, 116.8, 40.2]  (经度, 纬度, 经度, 纬度)

// 计算需要的瓦片数量
const tileWidth = 1024;  // 瓦片宽度（像素）
const tileHeight = 1024; // 瓦片高度（像素）

// 地理范围
const lonRange = 116.8 - 116.0 = 0.8 度
const latRange = 40.2 - 39.5 = 0.7 度

// 需要的瓦片数量
const tilesX = Math.ceil(lonRange / (tileWidth * resolution))
const tilesY = Math.ceil(latRange / (tileHeight * resolution))
```

**步骤3：生成 WMS 请求 URL**
```javascript
// 对于第一个瓦片
const bbox = "116.0,39.5,116.8,40.2";
const width = 1024;
const height = 1024;
const resolution = 0.3515625;  // ✅ 与服务端匹配

// 生成的 URL
GET /map/getmap?
  SERVICE=WMS&
  VERSION=1.1.0&
  REQUEST=GetMap&
  BBOX=116.0,39.5,116.8,40.2&
  WIDTH=1024&
  HEIGHT=1024&
  CRS=EPSG:4326&
  RESOLUTION=0.3515625  ← 关键：必须与服务端匹配
```

**步骤4：服务端处理**
```javascript
// 服务端接收到请求
// 检查：RESOLUTION=0.3515625 是否支持？
// ✅ 支持 → 生成对应分辨率的瓦片
// ❌ 不支持 → 返回错误或使用默认分辨率
```

**步骤5：客户端渲染**
```javascript
// 如果分辨率匹配：
// - 瓦片大小正确
// - 瓦片完美拼接
// - 显示正常 ✅

// 如果分辨率不匹配：
// - 瓦片大小错误
// - 瓦片错位
// - 显示异常 ❌
```

#### 场景A：标准瓦片（256×256）

```javascript
// 缩放级别 0

// 缩放级别 1
分辨率 = 0.703125 / 2 = 0.3515625 度/像素

分辨率 = 0.3515625 / 2 = 0.17578125 度/像素
```

#### 场景B：大瓦片（1024×1024）- 项目中使用

```javascript
// 缩放级别 0
```

## 如何确定服务端分辨率

### 方法1：查看服务端文档

```javascript
// 服务端可能提供 GetCapabilities 接口
GET /ows/?SERVICE=WMS&VERSION=1.1.0&REQUEST=GetCapabilities

// 返回 XML，包含支持的分辨率信息
<Layer>
  <ScaleHint min="0.17578125" max="0.703125"/>
</Layer>
```

### 方法2：测试不同分辨率

```javascript
// 测试分辨率 0.703125
GET /map/getmap?BBOX=-180,90,0,0&WIDTH=1024&HEIGHT=1024

// 如果返回正常 → 支持
// 如果返回错误 → 不支持
```

### 方法3：查看服务端配置

```javascript
// GeoServer 配置文件中可能包含：
<resolutions>
  <double>0.703125</double>
  <double>0.3515625</double>
  <double>0.17578125</double>
</resolutions>
```

## 项目中的实际配置

### 当前配置分析

```javascript
// Map2D.vue 第73-83行
const customTileGrid = new TileGrid({
  tileSize: 1024,        // 瓦片大小：1024×1024
  origin: [-180, 90],     // 网格原点
  resolutions: [
    0.703125,      // 级别 0
    0.3515625,     // 级别 1
    0.17578125,    // 级别 2
  ],

```

### 分辨率计算验证

#### 如果使用 256×256 瓦片：
```
级别 0：360 / (2 × 256) = 0.703125 ✅ 匹配
级别 1：0.703125 / 2 = 0.3515625 ✅ 匹配
级别 2：0.3515625 / 2 = 0.17578125 ✅ 匹配
```

#### 如果使用 1024×1024 瓦片：
```
级别 0：360 / (2 × 1024) = 0.17578125 ❌ 不匹配（应该是 0.703125）
级别 1：0.17578125 / 2 = 0.087890625 ❌ 不匹配（应该是 0.3515625）
级别 2：0.087890625 / 2 = 0.0439453125 ❌ 不匹配（应该是 0.17578125）
```

**结论**：项目中的 resolutions 配置是基于 **256×256 瓦片**计算的，即使 tileSize 设置为 1024。

这可能是因为：
1. 服务端实际返回的是 256×256 的瓦片
2. 或者 WMS 请求中的 WIDTH 和 HEIGHT 参数被设置为 256

## 总结

### 核心要点

1. **分辨率定义**：每个像素代表的地理距离（度/像素）
2. **匹配重要性**：客户端和服务端分辨率必须一致，否则瓦片错位
3. **计算公式**：`分辨率 = 地理范围 / (瓦片数量 × 瓦片宽度)`
4. **匹配原则**：resolutions 数组必须与服务端支持的缩放级别和分辨率完全一致

### 实际应用

- ✅ **正确**：根据服务端实际支持的分辨率配置 resolutions 数组
- ❌ **错误**：随意设置 resolutions，不匹配服务端配置
- ✅ **最佳实践**：通过 GetCapabilities 接口或测试确定服务端分辨率

### 项目中的配置

项目使用标准分辨率配置（基于 256×256 瓦片）：
- 级别 0：0.703125
- 级别 1：0.3515625
- 级别 2：0.17578125

这些分辨率必须与服务端 WMS 服务支持的分辨率完全匹配，才能确保瓦片正确加载和拼接。
